# 邮件夜间模式与底部预测列设计

日期：2026-07-31
状态：已确认视觉方向，待书面说明复核

## 问题

当前 HTML 邮件的数字表头右对齐，但数据单元格使用邮件客户端默认对齐，导致“最新值”“1 日”“7 日”与表头错位。邮件主体使用大面积白色背景，夜间阅读时亮度过高。邮件也没有展示网页已有的“本次熊市低点预期”，用户需要在邮件和网页之间切换才能比较当前值与模型预测值。

## 目标

- 采用用户确认的 A 版结构，并改为固定夜间模式。
- 让 Gmail 电脑网页端的表头、数值和边框严格对齐。
- 在约 680px 的电脑端主体宽度下保持清晰的信息密度。
- 在 Gmail 手机端保持五列表格可读，不出现横向溢出。
- 新增“预测底部值”列，并与网页“本次熊市低点预期”使用同一份数据。
- 保留日报、预警和测试邮件现有的主题与发送逻辑。

## 非目标

- 不改变风险分、七日展望、预警阈值或邮件发送频率。
- 不修改历史底部样本、行情数据源或预测公式的业务含义。
- 不为邮件增加交互组件、远程图片、追踪像素或外部字体。
- 不根据收件人系统主题自动切换明暗模式；本次邮件始终使用夜间模式。

## 方案选择

采用“数据更新时计算并持久化预测结果”的方案。`scripts/model.py` 提供纯 Python 预测函数，`scripts/update_data.py` 在生成数据时将结果写入 `assessment.bottomForecast`。网页和邮件都优先读取该字段，网页仅在读取旧版数据时保留现有 JavaScript 计算作为兼容回退。

未采用在 `scripts/notify.py` 中单独复制预测公式的方案，因为网页和邮件会形成两套长期可能漂移的实现。也不在发送邮件时启动 JavaScript 运行时，因为这会增加 GitHub Actions 的依赖和故障面。

## 数据设计

`assessment.bottomForecast` 的结构为：

```json
{
  "asOf": "2026-07-30",
  "targetDate": "2026-10-16",
  "values": {
    "price": 34268.0,
    "nupl": -0.507,
    "realizedPrice": 51626.0,
    "mvrv": 0.66,
    "mvrvZ": -0.47,
    "wwi": 0.031,
    "riskScore": 0.7
  }
}
```

预测函数复用网页现有逻辑：从四轮熊市窗口选取最低日线价格样本，以越新的周期越高权重计算底部估值基准；结合当前周期最低 MVRV、最近约 180 天已实现价格趋势、区块高度和近期日均出块数，计算预测日期及各指标预测值。

若某项输入不足，该项预测值为 `null`。网页和邮件将其显示为“暂不可用”或 `--`，不阻止其他指标和邮件发送。

## 邮件设计

邮件使用兼容邮件客户端的表格布局和内联样式，主体最大宽度为 680px。背景使用低亮度深灰而非纯黑，正文使用柔和浅灰而非纯白：

- 外层背景：`#0e1113`
- 邮件主体：`#181c1f`
- 顶部区域：`#0d1113`
- 主文字：`#e8edef`
- 次要文字：`#aebbc1`
- 状态强调：`#ff7658`
- 表格边框：`#465158`
- 预测列背景：`#312c20`
- 预测列文字：`#f2d889`

顶部依次显示产品标识、邮件标题和北京时间数据状态。正文依次显示风险状态、综合风险分、未来七日判断、判断说明和指标表格。页脚明确说明预测值是动态模型估计，并非价格承诺，也不构成投资建议。

指标表格列顺序固定为“指标 / 最新值 / 预测底部值 / 1 日 / 7 日”。首列左对齐，其余四列右对齐，所有单元格使用一致的内边距、完整边框和等宽数字。列宽约为 29% / 18% / 25% / 14% / 14%。预测列使用暗金色背景区分，但不使用高亮黄色。

手机端减小外边距、字号和单元格内边距，保持相同五列结构。指标名称允许在必要时换行，数值保持单行。邮件不依赖 CSS Grid、Flexbox、JavaScript 或远程资源。

纯文本替代内容同步新增“预测底部值”列，并继续保留风险状态、七日判断和免责声明。

## 兼容与错误处理

- `assessment.bottomForecast` 缺失时，邮件仍正常生成，并将该列显示为 `--`。
- 网页读取新版数据时直接使用持久化预测；读取旧数据时继续调用现有 `expectedBottomForecast` 回退函数。
- 每个关键容器同时使用内联背景色；布局表格使用 `role="presentation"`，数据表格保留语义表头。
- 邮件地址、应用密码和其他私密信息不写入 HTML、日志、测试快照或仓库。
- SMTP 错误仍沿用当前脱敏异常处理。

## 成功标准

- Gmail 电脑端显示固定夜间模式，阅读时不再出现大面积白色背景。
- 五列表头与每行数据严格对齐，表格纵横边框清晰可见。
- 邮件中的预测底部值与同一次数据更新后的网页完全一致。
- Gmail 手机端没有横向滚动或文字遮挡。
- 现有日报、预警、测试模式和隐私保护测试继续通过。
